# Access Form 管理後台製作步驟

> 給昱妏（晨嬡協助）。照著做大約 1.5–2 小時。課堂 W12 教 Form 之後就能做。

> **自動產生版本**：`db\build_admin_frontend.py` 會用程式做出和本文件相同的後台（`db/後台.accdb`），
> 並把 `db\` 加入 Access 信任位置，主選單按鈕不用按「啟用內容」。
> `tests\verify_access_frontend.py` 會自動檢查表單、子表單連動、下拉選單、驗證規則、一鍵下架，
> 以及 Access 開著時網頁能否同時讀寫（18 項）。
>
> **分工**：商家上架、管理員審核（通過／退回）、違規下架、統計，主要都在**網頁**的商家後台與管理員後台做
> （Access 沒有使用者權限分級，網頁由後端檢查角色）。這個 Access 後台是給管理員直接維護資料、
> 以及在期末報告示範 Access 表單用的。
> 自動版是備案；期末報告建議還是由組員照下面步驟手做一次，才能說明做法。
>
> 程式做法上踩到的雷（手做不會遇到，記錄給之後修改程式的人）：
> 先改表單名稱（Rename）再建新表單（CreateForm）會讓 Access 當掉，所以要全部建完再改名；
> 用 LoadFromText 載入 VBA 模組時檔案必須是 Big5 編碼；不在信任位置的檔案，VBA 自訂函式會被停用。

## 0. 先決定：表單放在哪個檔案

`db/build_db.py` 每次執行都會**整個重建** `events.accdb`，如果把表單做在裡面，下次重建表單就不見了。
所以採用 Access 常見的「**前端／後端分離**」：

| 檔案 | 放什麼 | 誰改 |
|---|---|---|
| `db/events.accdb`（後端） | 8 張資料表、37 個已存好的查詢 | 由程式產生；正式版由晏均維護 |
| `db/後台.accdb`（前端） | 表單、按鈕、VBA；資料表用「連結」的 | 昱妏 |

網頁後端（Python）和 Access 表單連的是同一個 `events.accdb`，所以在表單裡新增、修改的活動，網頁重新整理就看得到。

> 不想分兩個檔也可以直接在 `events.accdb` 裡做表單，但**做完後就不能再跑 `build_db.py`**，之後資料只能從表單或匯入功能維護。

## 1. 建立前端檔並連結資料表

1. Access →「空白資料庫」→ 檔名 `後台.accdb`，存在 `db/` 資料夾。
2. 「外部資料」→「新增資料來源」→「從資料庫」→「Access」。
3. 檔案選 `events.accdb`，選「**以建立連結資料表的方式連結至資料來源**」→ 確定。
4. 全選 8 張資料表 → 確定。左側會出現 8 張前面有箭頭圖示的資料表（＝連結）。
5. 再做一次步驟 2，這次選「**匯入**」，切到「查詢」頁籤，選所有 `統計_`、`管理_`、`提醒_` 開頭的查詢 → 確定。

> 如果 `events.accdb` 搬了位置：「外部資料」→「連結資料表管理員」→ 全選 → 勾「永遠提示新位置」→ 重新指定檔案。

## 2. 活動管理表單（主表單＋優惠子表單）

這是後台最重要的一張表單：一個畫面看一場活動和它的所有優惠。

1. 「建立」→「表單精靈」。
2. 「資料表/查詢」選 `EventTable`，加入全部欄位**除了** `EventID` 以外都可以加（EventID 是自動編號，也可以加進來只看不改）。
3. 同一個畫面，「資料表/查詢」改選 `DiscountTable`，加入 `DiscountType_FK`、`DiscountDescription`、`DiscountPrice`、`DiscountStartDate`、`DiscountEndDate`。
4. 下一步：「您要如何檢視資料」選「**依 EventTable**」→「**含有子表單的表單**」。
5. 子表單版面選「資料工作表」→ 表單標題：`活動管理`，子表單標題：`優惠` → 完成。

因為資料表已設好「查閱」欄位，`EventCategory_FK`、`EventVenue_FK`、`EventOrganizer_FK`、`DiscountType_FK` 會自動變成**下拉選單**，顯示名稱而不是編號。
驗證規則（結束日不能早於開始日、價格不能是負數…）在資料表層級就設好了，表單裡輸入錯誤會自動跳出中文提示。

**美化建議**（「設計檢視」裡調整）：
- `EventDescription` 文字方塊拉高，屬性「捲軸」設為「垂直」。
- `EventStatus`（審核狀態）改成下拉選單：在文字方塊上按右鍵 →「變更為」→「下拉式方塊」，屬性「資料列來源類型」選「值清單」，「資料列來源」填 `"待審核";"上架中";"已退回";"已下架"`。
- `EventOrganizer_FK`（上架商家）的下拉選單，「資料列來源」可改成只列商家和管理員：`SELECT UserID, UserName FROM UserTable WHERE UserRole IN ('商家', '管理員')`。
- 表單頁首加一個「搜尋活動名稱」：在屬性表的「資料」→「篩選」用 `[EventTitle] Like "*" & [Forms]![活動管理]![txt搜尋] & "*"`，或直接用 Access 內建的「尋找」（Ctrl＋F）就夠了。

## 3. 場館管理、優惠類型管理表單

1. 在左側選 `VenueTable` →「建立」→「表單」（一鍵產生）→ 存成 `場館管理`。
2. 選 `DiscountTypeTable` →「建立」→「其他表單」→「多重項目」→ 存成 `優惠類型管理`。
3. `CategoryTable` 同上 → 存成 `類別管理`。

## 4. 主選單（含一鍵下架按鈕）

1. 「建立」→「空白表單」→ 切到「設計檢視」，存成 `主選單`。
2. 加一個標籤當標題：「探點 管理後台」。
3. 用「按鈕」工具拉出按鈕。按鈕精靈出現時：
   - `活動管理`：類別「表單作業」→「開啟表單」→ 選 `活動管理`。
   - `場館管理`、`類別管理`、`優惠類型管理`：同上。
   - `各地區活動數`：類別「其他」→「執行查詢」→ 選 `統計_各地區活動數`。
   - `熱門收藏排行`：同上，選 `統計_熱門收藏排行`。
   - `待審核活動`：同上，選 `管理_待審核活動`（審核本身請用網頁的管理員後台）。
   - `早鳥即將截止`：同上，選 `提醒_早鳥即將截止`（執行時會問「幾天內」）。
4. **一鍵下架**按鈕要確認後才執行，所以用 VBA：
   - 拉一個按鈕，精靈按「取消」，屬性表「其他」→「名稱」改成 `btn下架`，「格式」→「標題」改成 `一鍵下架已結束活動`。
   - 屬性表「事件」→「按一下」→ 點「…」→「程式碼產生器」，貼上：

```vba
Private Sub btn下架_Click()
    Dim n As Long
    n = DCount("*", "EventTable", "EventEndDate < Date() AND EventStatus = '上架中'")
    If n = 0 Then
        MsgBox "目前沒有需要下架的活動。", vbInformation
        Exit Sub
    End If
    If MsgBox("有 " & n & " 場活動已經結束但還在上架中，確定要全部下架嗎？" & vbCrLf & _
              "（狀態改成「已下架」，資料不會刪除）", vbYesNo + vbQuestion, "一鍵下架") = vbYes Then
        CurrentDb.Execute "管理_一鍵下架已結束活動", dbFailOnError
        MsgBox "已下架 " & n & " 場活動。", vbInformation
    End If
End Sub
```

   - 按「預覽待下架」按鈕可以先看會影響哪些活動：按鈕精靈 →「執行查詢」→ `管理_預覽待下架活動`。

5. 「檔案」→「選項」→「目前資料庫」→「顯示表單」選 `主選單`，打開檔案就會先出現主選單。

> 網頁後端在伺服器啟動、打開商家或管理員後台時也會自動執行同一個查詢（`管理_一鍵下架已結束活動`），
> 所以這顆按鈕是給「只開 Access、沒開網頁」的時候用的。

> VBA 無法執行時：檔案打開後上方黃色列按「啟用內容」。

## 5. Demo 腳本建議（期末報告）

1. 打開 `後台.accdb` → 主選單。
2. 「活動管理」→ 新增一場活動，下拉選類別、場館、上架商家（選管理員），審核狀態選「上架中」，在子表單加一個學生優惠。
3. 故意把結束日填得比開始日早 → 展示驗證規則的中文提示。
4. 切到網頁搜尋剛剛新增的活動 → 出現了（同一個資料庫）。
5. 回主選單按「一鍵下架」→ 顯示幾場已結束 → 確定 → 網頁上這些活動消失。
6. 「熱門收藏排行」→ 展示 GROUP BY＋COUNT＋TOP 的結果。

| 待審核活動 | 管理_待審核活動 | `sql/admin/pending_events.sql` |
