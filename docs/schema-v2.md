## 為什麼要改

接文化部開放資料時會遇到兩個問題：

1. **一場活動可能在多個場館、多個時間舉行**（巡演、多場次）。原本 `EventTable` 只有一個 `EventVenue_FK`，放不下。
2. **票價常常不是單一數字**，例如「500–2000」「免費」「依現場公告」。

另外，**收藏不能重複**的規則原本就有寫，這次確認以複合唯一索引實作。

## 修改 1：新增場次表 `SessionTable`（變成 9 張表）

| 欄位名稱 | 欄位標題 | 資料型態 | 可空值 | 說明 |
|---|---|---|---|---|
| SessionID (PK) | 場次編號 | 自動編號 | X | |
| SessionEvent_FK (FK) | 場次所屬活動 | 查閱（長整數） | X | 連結 EventTable.EventID；刪除活動時一併刪除場次 |
| SessionVenue_FK (FK) | 場次舉辦場館 | 查閱（長整數） | X | 連結 VenueTable.VenueID |
| SessionStartTime | 場次開始時間 | 日期/時間 | X | 格式 yyyy/mm/dd hh:nn |
| SessionEndTime | 場次結束時間 | 日期/時間 | V | 資料表驗證規則：`[SessionEndTime]>=[SessionStartTime] Or [SessionEndTime] Is Null` |

- **`EventTable` 刪除 `EventVenue_FK`**，場館改由場次表記錄。
- 展覽這類「一段期間都在同一地點」的活動，就建 **1 筆場次**，起訖時間等於展期。
- `EventStartDate`、`EventEndDate` **保留**：代表整個活動的期間，搜尋「日期區間」時直接用，不必每次去場次表算。

關係變成：活動 1 ─ 多 場次 多 ─ 1 場館（活動和場館是多對多，透過場次表連接）。
依縣市／地區查詢時：活動 → 場次 → 場館 → 縣市。

## 修改 2：票價規則

| 欄位 | 修改 |
|---|---|
| `EventOriginalPrice` | 改成**可空值**、拿掉預設值 0。意義：**最低票價**；`0` = 免費；**空值 = 票價不明**。驗證規則 `>=0` 保留（空值不受影響） |
| 新增 `EventPriceNote` | 短文字 100，可空值，標題「票價原始說明」。保留原始寫法，例如「500–2000（依座位區）」「依現場公告」 |

網頁顯示：有數字顯示「NT$500 起」，0 顯示「免費」，空值顯示「票價未定」，有原始說明就附在後面。

## 修改 3：收藏不能重複（確認）

`SaveTable` 建立複合唯一索引 `UQ_SaveUser_FK_SaveEvent_FK`（SaveUser_FK + SaveEvent_FK）。
Access 做法：資料表設計 → 索引 → 新增一個索引名稱，兩列分別選這兩個欄位，「唯一」設為「是」。

## 修改 4：優惠截止日期空值（確認）

`DiscountEndDate` **允許空值，空值代表沒有截止日**。「目前有效的優惠」條件：

```sql
(DiscountStartDate IS NULL OR DiscountStartDate <= Date())
AND (DiscountEndDate IS NULL OR DiscountEndDate >= Date())
```

資料表驗證規則多加一個條件：`[DiscountEndDate]>=[DiscountStartDate] Or [DiscountEndDate] Is Null Or [DiscountStartDate] Is Null`
（明確允許「開始日期空值、截止日期有值」，也就是「優惠從活動開始就有、某天截止」的情況）。

「早鳥優惠必填截止日期」目前只寫在建檔規則裡，資料表本身不擋（擋的話驗證規則要寫死早鳥的編號）。

## 其他順手決定的事（可以再討論）

- **宜蘭縣歸「東部」**（組內決定）。縣市順序：北部 6、中部 5、南部 5、東部 3（宜蘭、花蓮、臺東）、離島 3。
- **關聯的串聯刪除**：刪除活動時，它的場次、優惠、收藏一起刪；刪除使用者時，收藏一起刪。縣市、類別、場館、優惠類型如果還有資料在用，就不允許刪除。
- **建議的預設類別**：展覽、講座、工作坊、科普展覽、研習營隊、音樂表演、戲劇、舞蹈、市集、體育賽事。
  （「舞蹈」是接文化部開放資料時加的，對應文化部的舞蹈類活動，約 70 筆。）
- **建議的預設優惠類型**：學生優惠、早鳥優惠、敬老優惠、團體優惠。
- 試算表裡 `DiscountType_FK` 的範例值顯示成 `1900-01-01 00:00:00`、`VenueID` 顯示成 `1900-01-12`，是 Excel 把數字當成日期了，請把儲存格格式改回「數值」。
